# محرك الذكاء الاصطناعي الذاتي — جرد البنية والتصميم

الحالة: المرحلة الصفرية (الجرد) مكتملة بقدر ما سمحت به أدوات CranL، والتصميم جاهز للمراجعة. لم يُنشر شيء على CranL، ولم يُعدَّل أي إعداد في الإنتاج.

---

## 1. نتائج الجرد

### المستودع والتطبيق

| البند | الحالة |
|---|---|
| الواجهة | React 18 + Vite 5 + Tailwind، تطبيق صفحة واحدة |
| الخادم | Express 4 على Node.js 20 (Nixpacks)، تطبيق واحد يخدم الواجهة والـ API |
| قاعدة البيانات | MySQL 8.4 عبر Prisma 5، عشرة جداول أصلية + جدولان جديدان محلياً (`ai_suggestions`، `ai_learning_profiles`) |
| المصادقة | JWT قصير + رمز تحديث في كعكة، محدِّد معدل لكل مستخدم على مسارات الذكاء الاصطناعي (25/ساعة) |
| ما بُني محلياً | طبقة مزوّدين موحّدة، نموذج محلي داخل العملية (node-llama-cpp)، فحص ضد الاختلاق والحذف، ذاكرة تعلّم، مكتبة فحص عربية بلا نموذج |

### لماذا فشل الذكاء الاصطناعي القديم

1. أسماء نماذج تخمينية (`gemini-3.6-flash` ثم سلسلة بدائل) ونموذج Claude متقاعد (`claude-3-5-sonnet-20241022`).
2. عند فشل المزوّد يرجع «محرك بديل» من قواعد نصية يتظاهر بالذكاء الاصطناعي ويُفسد الكلمات.
3. الترجمة البديلة عبر واجهات Google غير الرسمية وMyMemory، أي إرسال نصوص المستخدم لأطراف ثالثة.
4. العمليات الجماعية تكتب فوق الإدخالات مباشرة دون مراجعة.

كل ذلك أُزيل أو أُوقف في الفرع المحلي.

### CranL

| البند | النتيجة | المصدر |
|---|---|---|
| الخطة | Enterprise | `get_account` |
| الطوابير (Queues) | متاحة: 100 مليون رسالة/شهر، حتى 256 كيلوبايت للرسالة، احتفاظ حتى 14 يوماً، إعادة محاولة وطوابير رسائل ميتة مدمجة | `get_queues_overview` |
| تطبيقات العمال (Workers) | متاحة: تطبيق بلا عنوان عام، نسخ 0–20، توسّع تلقائي حسب تراكم الطابور مع الإيقاف عند الصفر | توثيق CranL |
| الأقراص الدائمة | متاحة (`add_volume`)؛ لا يوجد قرص مرتبط بتطبيق الموقع حالياً | `list_volumes` |
| تطبيق إضافي | مشمول في الخطة دون تكلفة إضافية (طُلب التقدير لـ 4 vCPU و8 جيجا) | `estimate_cost` |
| **المعالج والذاكرة الفعليان للتطبيق** | **غير معروفين** | أداة القياس رجعت بخطأ داخلي من CranL ثلاث مرات، وتنفيذ الأوامر داخل الحاوية يرجع «تعذر قراءة المخرجات» حتى لأمر `echo` |

**القيد الحرج:** لا يمكن اختيار النموذج نهائياً قبل معرفة ذاكرة الحاوية ومعالجها. يلزم إما قراءتها من لوحة CranL، أو نشر نقطة فحص بسيطة تعيد `os.cpus()` وحد ذاكرة cgroup (يتطلب نشراً، وهو موقوف حتى إذنك).

### قياسات محلية سابقة (Qwen2.5 7B Q4_K_M)

| الظرف | الزمن | الذاكرة |
|---|---|---|
| كرت الشاشة RTX 4060 Ti | 5–20 ثانية للإدخال | — |
| معالج فقط، خيطان | 77–99 ثانية للإدخال القصير | ~7.8 جيجا للعملية |

الخلاصة: 7B ثقيل على خادم بلا كرت شاشة. لهذا تُختبر النماذج الصغيرة التالية.

## 3. التصميم

```
المتصفح
  │  (مصادقة، تحقق، حد معدل)
تطبيق الموقع (Express) ── بوابة الذكاء الاصطناعي
  │  ├─ الموجّه: هل تكفي المكتبة الحتمية؟ ← نعم: رد فوري (مللي ثوانٍ)
  │  └─ لا: إنشاء مهمة ← طابور CranL ← رقم المهمة للمتصفح
  │
طابور CranL (إعادة محاولة، رسائل ميتة، منع التكرار)
  │
تطبيق عامل (Worker) بلا عنوان عام
  ├─ النموذج (llama.cpp داخل العملية) على قرص دائم /models
  ├─ مهارة واحدة في كل مرة، حد زمني، إلغاء
  └─ يكتب النتيجة في MySQL ← المتصفح يستعلم عن حالة المهمة
```

**لماذا عامل منفصل:** النموذج لا يعيش في عملية الموقع، فلا يبطئه ولا يستهلك ذاكرته. يتوسع العامل مع الطابور ويتوقف عند الصفر حين لا توجد مهام.

**بديل إن لم تتسع الموارد لعامل:** النموذج داخل عملية الموقع مع حد ذاكرة صارم ومهمة واحدة في كل مرة، أو المكتبة الحتمية وحدها.

### الموجّه

| نوع الطلب | المنفّذ |
|---|---|
| إملاء، ترقيم، مصطلحات، أقسام ناقصة، تكرار، مبالغة | المكتبة الحتمية (بُنيت ومختبرة) |
| تدقيق نحوي | المكتبة أولاً، ثم النموذج عند الطلب |
| صياغة أكاديمية، تحسين وضوح، إيجاز، ترجمة، توسيع من معلومات مُعطاة | النموذج عبر الطابور |
| بحث دلالي في مستندات المتدرب | نموذج تضمين صغير + فهرس (مرحلة لاحقة) |

### المهارات

كل مهارة ملف واحد: معرّف، وصف، مخطط إدخال وإخراج (Zod)، تعليمات، متطلبات النموذج، فحوص جودة (الاختلاق، الحذف، الانحراف اللغوي)، حد زمني، مقاييس تنفيذ. المهارات الحالية في `server/src/ai/tasks.ts` تُنقل إلى هذا الشكل.

### الجداول الإضافية المقترحة

| الجدول | الغرض |
|---|---|
| `ai_jobs` | المهمة: المهارة، الحالة، المحاولات، النتيجة، رقم الاقتراح |
| `ai_execution_logs` | زمن التنفيذ، الرموز، النموذج، نتيجة فحوص الجودة |
| `ai_documents` و`ai_document_chunks` | لمرحلة البحث في المستندات، مع ربط كل جزء بمالكه |

كلها جداول جديدة، دون أي تعديل على الجداول الحالية، عبر ترحيلات Prisma مراجَعة.

## 4. ما يحتاج قرار صاحب المشروع

1. **تنزيل النماذج الثلاثة للمقارنة** (نحو 5 جيجا).
2. **معرفة موارد حاوية التطبيق على CranL** من اللوحة.
3. **لاحقاً:** إنشاء تطبيق عامل وطابور وقرص دائم على CranL (تغييرات في البنية تحتاج إذناً صريحاً).
